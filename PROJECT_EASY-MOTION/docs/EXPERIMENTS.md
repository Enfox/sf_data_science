# Эксперименты и валидация

## Что сравнивалось

Использована одна модель: Keypoint R-CNN ResNet-50 FPN, COCO_V1. Менялось только правило
сопоставления времени. Это два эксперимента с обработкой данных, а не обучение двух моделей.

| Параметр | Значение |
| --- | --- |
| Порог человека | score > 0.9 |
| Порог ключевой точки | score > 2.0 на обоих кадрах |
| Минимум общих точек | 6 |
| Пространственное совмещение | Полное аффинное, метод наименьших квадратов |
| Веса L1 | Score ключевых точек повторения |
| Частота контрольного режима | 30 пар/с |
| Обучение, эпохи, learning rate | Не применяются: используются готовые веса |

## Полученные результаты

| Эксперимент | Пары | Среднее d_cos | Среднее L1, px | Медиана L1, px | Среднее центрированное d_cos |
| --- | ---: | ---: | ---: | ---: | ---: |
| Relative: полные 3 и 4 с | 120/120 | 0.001987 | 51.357 | 45.949 | 0.069395 |
| Realtime: общие первые 3 с | 90/90 | 0.000861 | 30.437 | 29.887 | 0.029952 |

Аффинных отражений: 75 в первом режиме, 22 — во втором. Все исходные значения
без округления находятся в [`results/summary.json`](../results/summary.json),
покадровые — в CSV каждого режима.

При равном прошедшем времени получены меньшие расстояния. Охват и соответствия кадров
различаются, поэтому результаты не следует трактовать как прирост качества модели.
Выбор лучшего режима по метрике после просмотра данных не используется для итоговой оценки.

## Как устроена проверка

1. Декодирование всех кадров, проверка FPS и временных меток.
2. Визуальная проверка выбора спортсмена, особенно рядом с манекеном и при приземлении.
3. Проверки функций на известных примерах: косинус, взвешенная сумма, аффинное преобразование,
   вырожденные координаты, отсутствие человека и ненадёжные точки.
4. Сопоставление покадровых метрик с проверенным ноутбуком четвёртого спринта.
5. Запуск основного скрипта и ноутбука, проверка сохранённых CSV, графика и MP4.

Проверочный запуск: Python 3.11.7, PyTorch 2.5.1 + CUDA 12.1, torchvision 0.20.1,
OpenCV 4.11.0, Windows. Прошли 4 теста и все 7 ячеек кода ноутбука.
Экспортированы H.264-видео 720 × 800, 30 FPS: 120 кадров (4 с) и 90 кадров (3 с).
Номера сопоставленных кадров совпадают со спринтом IV. При повторном GPU-запуске
получена небольшая численная вариация предсказаний: максимальное отличие покадрового
L1 около 0,050 px, среднее отличие контрольного режима около 0,00055 px.
Таблица выше соответствует сохранённому `summary.json`; побитовая идентичность
результатов на разных запусках и устройствах не предполагается.

Здесь нет `train/validation/test`: модель не обучалась, а два видео не дают независимой
оценки качества. Это демонстрация работоспособности и проверка реализации.
Для проверки обобщающей способности нужны новые люди, другие ракурсы, разные движения
и независимая разметка. В таком расширении делить данные следует по людям/записям,
а не случайно по соседним кадрам одного видео.

## Что пока не измерено

Точность ключевых точек относительно ручной разметки, качество спортивной техники,
скорость работы на разных устройствах, пользовательская польза и финансовый эффект.
Возможная продуктовая метрика будущего приложения — доля загрузок, для которых удалось
построить сравнение. На реальных пользователях она не измерялась.
