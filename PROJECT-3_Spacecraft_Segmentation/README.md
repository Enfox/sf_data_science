### Описание проекта

Автоматическая сегментация космических аппаратов — важная задача компьютерного зрения для анализа спутниковых изображений, синтетических датасетов, контроля формы объекта и выделения его конструктивных элементов. В отличие от обычной классификации, здесь требуется не просто определить наличие объекта на изображении, а **попиксельно отделить его части** и получить маски для каждого значимого компонента.

В рамках данной работы решается задача **instance segmentation**: на вход подаётся изображение космического аппарата, на выходе модель возвращает набор масок, bounding boxes, классов и confidence-score для найденных частей объекта.

Ключевая особенность проекта — перевод цветных RGB-масок датасета в формат, подходящий для `torchvision` Mask R-CNN: для каждой части аппарата формируется отдельная бинарная маска, ограничивающая рамка и метка класса.

### Какой кейс решаем?

Задача формализуется как **сегментация частей космического аппарата с тремя целевыми классами**:

- `body` — корпус аппарата;
- `solar_panel` — солнечные панели;
- `antenna` — антенны.

Модель должна научиться не только находить объект на изображении, но и разделять его на функциональные компоненты. Это ближе к реальной инженерной задаче, чем бинарная сегментация «объект / фон», потому что разные части аппарата имеют разную форму, размер и визуальную сложность.

**Ключевые вызовы задачи:**
- **Сложная форма объекта**: корпус, панели и антенны могут сильно отличаться по размеру и геометрии.
- **Мелкие элементы**: антенны занимают небольшую площадь, поэтому модель хуже обучается на этом классе и чаще теряет его при предсказании.
- **Цветные маски вместо готовых COCO-аннотаций**: исходную разметку нужно преобразовать в формат `boxes / labels / masks`, который ожидает Mask R-CNN.
- **Ограничения локального окружения**: обучение выполнялось в Windows / VS Code, поэтому для `DataLoader` использовался `num_workers=0`.

Решение этих проблем достигается через **transfer learning** с Mask R-CNN, предобученной на COCO, аккуратную подготовку датасета, аугментации изображений и расчёт нескольких метрик качества сегментации.

### Информация о данных

- **Источник**: папка `Final_dataset`, подключаемая из Google Drive.
- **Тип данных**: цветные изображения космических аппаратов.
- **Формат аннотаций**: RGB-маски, где цвет пикселя задаёт класс части аппарата.
- **Количество изображений**: 3117.
- **Разбиение**: 2517 изображений для обучения и 600 изображений для валидации.
- **Количество целевых классов**: 3 (`body`, `solar_panel`, `antenna`) + фоновый класс `background`.

**Соответствие цветов и классов:**

| Цвет в RGB-маске | Класс | Описание |
|---|---|---|
| Зелёный канал | `body` | корпус космического аппарата |
| Красный канал | `solar_panel` | солнечная панель |
| Синий канал | `antenna` | антенна |
| Чёрный цвет | `background` | фон |

**Структура датасета:**

```text
Final_dataset/
├── images/
│   ├── train/          # обучающие изображения
│   └── val/            # валидационные изображения
├── mask/
│   ├── train/          # обучающие RGB-маски
│   └── val/            # валидационные RGB-маски
├── all_bbox.txt
└── ReadMe.txt
```

**Особенности подготовки данных:**
- служебные файлы вроде `.DS_Store` исключаются из списка изображений;
- изображение и маска сопоставляются по числовому индексу в имени файла;
- из одной цветной маски извлекаются бинарные маски для присутствующих частей аппарата;
- для каждой бинарной маски автоматически строится bounding box;
- вырожденные маски и боксы отбрасываются.

### Этапы работы над проектом

1. **Подготовка окружения и путей** — настройка локального пути к `Final_dataset`, проверка структуры папок `images` и `mask`.

2. **Проверка формата масок** — анализ уникальных RGB-цветов в маске и подтверждение соответствия каналов классам аппарата.

3. **Реализация датасета** — создание класса `SattDataset`, который читает изображения и маски, сопоставляет пары по индексу файла и формирует target в формате Mask R-CNN.

4. **Преобразование масок** — перевод цветной RGB-маски в набор бинарных масок по классам `body`, `solar_panel`, `antenna`.

5. **Визуальная проверка данных** — отрисовка изображений с наложенными масками и bounding boxes для train и validation выборок.

6. **Аугментация и ресайз** — приведение изображений к размеру 512×512, горизонтальный flip, изменение яркости/контраста и перевод в тензоры.

7. **Создание модели** — загрузка `maskrcnn_resnet50_fpn(weights="DEFAULT")`, замена box predictor и mask predictor под 4 класса: 3 части аппарата + фон.

8. **Обучение модели** — обучение Mask R-CNN в обычном PyTorch training loop с `AdamW`, `StepLR` и mixed precision.

9. **Расчёт метрик** — оценка `mAP (segm)`, `mAP@0.50`, IoU по частям и foreground mIoU.

10. **Визуализация предсказаний** — сравнение ground truth масок с предсказаниями модели на валидационной выборке.

### Архитектура решения

#### Mask R-CNN ResNet50-FPN

```text
Входное изображение RGB
        3 × 512 × 512
              ↓
┌─────────────────────────────────────┐
│ Backbone: ResNet-50 + FPN            │
│ предобучен на COCO                   │
│ извлекает многомасштабные признаки   │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│ Region Proposal Network              │
│ предлагает области-кандидаты         │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│ ROI Heads                            │
│ классификация + уточнение bbox       │
│ box predictor заменён под 4 класса   │
└─────────────────────────────────────┘
              ↓
┌─────────────────────────────────────┐
│ Mask Head                            │
│ mask predictor заменён под 4 класса  │
│ строит бинарную маску для объекта    │
└─────────────────────────────────────┘
              ↓
Маски + bounding boxes + классы + scores
```

**Ключевые решения:**
- используется перенос обучения с COCO;
- `FastRCNNPredictor` заменён под `NUM_CLASSES = 4`;
- `MaskRCNNPredictor` заменён под 3 класса частей и фон;
- внутренний размер модели ограничен 512×512 для экономии VRAM;
- обучение выполняется с AMP, что ускоряет расчёты на GPU и снижает потребление памяти.

#### Гиперпараметры обучения

| Параметр | Значение |
|---|---|
| Модель | Mask R-CNN ResNet50-FPN |
| Предобученные веса | COCO / `weights="DEFAULT"` |
| Входное разрешение | 512 × 512 |
| Количество классов | 4: background + 3 части аппарата |
| Batch size | 2 |
| Эпохи | 10 |
| Оптимизатор | AdamW |
| Learning rate | 1e-4 |
| Weight decay | 1e-4 |
| LR scheduler | StepLR, `step_size=4`, `gamma=0.5` |
| AMP | включён при наличии CUDA |
| DataLoader | `num_workers=0` для Windows |
| Порог score для метрик | 0.5 |
| Сохранённая модель | `maskrcnn_spacecraft.pth` |

### Метрики качества

В проекте используются метрики, подходящие именно для instance segmentation:

- **mAP (segm)** — COCO-style mean Average Precision по маскам. Эта метрика оценивает качество instance segmentation с учётом точности найденных масок и confidence-score.

- **mAP@0.50** — mean Average Precision при пороге IoU = 0.50. Показывает, насколько хорошо модель находит и сегментирует объекты при более мягком критерии совпадения.

- **IoU по частям** — Intersection over Union для каждого класса: `body`, `solar_panel`, `antenna`. Позволяет увидеть, какие элементы аппарата сегментируются лучше или хуже.

- **mIoU по частям** — среднее IoU по трём целевым классам.

- **Foreground mIoU** — IoU для объединённой маски «аппарат против фона». Эта метрика показывает, насколько хорошо модель отделяет весь космический аппарат от фона без детализации по частям.

### Выводы

В рамках проекта успешно реализован полный pipeline **instance segmentation космических аппаратов** на PyTorch:

1. **Цветные RGB-маски преобразованы в формат Mask R-CNN.** Из исходных масок получены бинарные маски, классы и bounding boxes, необходимые для обучения модели `torchvision`.

2. **Transfer learning оказался ключевым решением.** Использование Mask R-CNN ResNet50-FPN с предобучением на COCO позволило получить рабочее качество без обучения тяжёлой модели с нуля.

3. **Модель хорошо отделяет аппарат от фона.** Foreground mIoU достиг `0.881`, то есть общая форма космического аппарата сегментируется достаточно уверенно.

4. **Детализация по частям сложнее, чем бинарная сегментация.** Средний mIoU по частям составил `0.686`, а самый проблемный класс — `antenna` с IoU `0.490`. Это ожидаемо: антенны тонкие, небольшие и часто занимают мало пикселей.

5. **Солнечные панели и корпус распознаются лучше всего.** Классы `solar_panel` и `body` получили IoU `0.804` и `0.764`, что говорит о стабильном выделении крупных частей аппарата.
