### Описание проекта

После пандемии COVID-19 автоматический контроль ношения масок стал востребованной задачей компьютерного зрения: от систем доступа в помещения до мониторинга соблюдения санитарных норм. В отличие от обычной классификации, здесь требуется не только понять, *есть ли* маска, но и **локализовать** каждое лицо на изображении и определить его статус.

В рамках данной работы решается задача **детектирования объектов (object detection)**: на вход подаётся фотография (часто с несколькими людьми в кадре), на выходе — набор ограничивающих рамок (bounding boxes) с указанием класса и уверенности для каждого обнаруженного лица.

Ключевая особенность проекта — **сравнение двух семейств детекторов**: двухуровневого (Faster R-CNN) и одноуровневого (YOLOv8). Цель — обосновать выбор архитектуры для production, опираясь на метрики **IoU** и **Average Precision**, а не на интуицию.

### Какой кейс решаем?

Задача формализуется как **детектирование объектов с тремя классами**:

- `with_mask` — маска надета правильно;
- `without_mask` — маска отсутствует;
- `mask_weared_incorrect` — маска надета неправильно (например, не закрывает нос).

Представьте, что компании выпала возможность помочь миру, обучив модель контроля ношения масок. Нужно сравнить два типа детекторов и предоставить отчёт руководству, обосновав выбор модели метриками.

**Ключевые вызовы задачи:**
- **Сильный дисбаланс классов**: `with_mask` — ~3200 объектов, `without_mask` — ~700, а `mask_weared_incorrect` — всего ~120. Редкий класс становится узким местом качества.
- **Мелкие объекты в толпе**: на многих снимках лица людей маленькие и плотно расположены, что усложняет и локализацию, и классификацию.
- **Ограниченный размер выборки**: 853 изображения — немного для обучения детектора с нуля.

Решение этих проблем достигается через **перенос обучения (Transfer Learning)** с моделей, предобученных на COCO, повышение входного разрешения и **усиленную аугментацию**, нацеленную на размножение примеров редкого класса.

### Информация о данных

- **Источник**: [Face Mask Detection (Kaggle)](https://www.kaggle.com/datasets/andrewmvd/face-mask-detection)
- **Тип данных**: цветные изображения (PNG/JPG)
- **Формат аннотаций**: Pascal VOC (XML) — для каждого изображения отдельный XML-файл с координатами рамок и классами
- **Количество изображений**: 853
- **Количество классов**: 3 (`with_mask`, `without_mask`, `mask_weared_incorrect`)
- **Разбиение**: 80% train / 20% validation (фиксированный `seed=1` — одинаковая валидация для обеих моделей, честное сравнение)

**Распределение объектов по классам (приблизительно):**

| Класс | Доля в датасете | Комментарий |
|---|---|---|
| `with_mask` | ~79% | Доминирующий класс |
| `without_mask` | ~18% | Умеренно представлен |
| `mask_weared_incorrect` | ~3% | Редкий класс — главная сложность |

**Структура датасета:**

```
data/
├── images/        (853 изображения)
│   ├── maksssksksss0.png
│   ├── maksssksksss1.png
│   └── ...
└── annotations/   (853 XML-файла Pascal VOC)
    ├── maksssksksss0.xml
    ├── maksssksksss1.xml
    └── ...
```

### Этапы работы над проектом

1. **Анализ задачи и подготовка окружения** — определение требований к качеству (`mAP@0.5 > 0.85`), настройка PyTorch + CUDA, установка Ultralytics.

2. **Загрузка данных через DataLoader** — реализация класса `FaceMaskDataset`, парсинг XML-аннотаций Pascal VOC, масштабирование изображений и координат рамок, защита от вырожденных и выходящих за границы боксов.

3. **Визуализация батча** — отрисовка одного батча с истинными рамками и подписями классов для проверки корректности загрузки данных.

4. **Выбор и обоснование моделей** — обоснование выбора Faster R-CNN (точность) и YOLOv8 (скорость) как представителей двух семейств детекторов.

5. **Обучение детектора №1 (Faster R-CNN)** — замена «головы» классификатора под 3 класса, обучение с косинусным графиком learning rate и аугментациями.

6. **Обучение детектора №2 (YOLOv8)** — конвертация аннотаций Pascal VOC → YOLO-формат (с сохранением того же train/val split), дообучение с аугментациями `mixup` и `copy_paste` против дисбаланса классов.

7. **Расчёт метрик** — собственная реализация IoU и Average Precision, построение Precision–Recall кривых для каждого класса, перекрёстная проверка через `torchmetrics`.

8. **Визуализация предсказаний** — сравнение предсказаний моделей с истинной разметкой, с акцентом на сложный редкий класс.

9. **Сравнение моделей и выводы** — сводная таблица AP по классам, проверка достижения целевого `mAP@0.5 > 0.85`, рекомендации по выбору модели для production.

### Архитектура решения

#### Подход 1 — Faster R-CNN (двухуровневый детектор)

```
Входное изображение (3 × 800 × 800)
            ↓
┌─────────────────────────────────────┐
│   Backbone: ResNet-50 + FPN          │
│   (предобучен на COCO)               │
│   Многомасштабные признаки —         │
│   ловит и крупные, и мелкие лица     │
└─────────────────────────────────────┘
            ↓
┌─────────────────────────────────────┐
│   Этап 1: Region Proposal Network    │
│   предлагает регионы-кандидаты       │
└─────────────────────────────────────┘
            ↓
┌─────────────────────────────────────┐
│   Этап 2: Box Predictor (ЗАМЕНЁН)    │
│   классификация регионов + уточнение │
│   рамок под 4 класса (3 + фон)       │
└─────────────────────────────────────┘
            ↓
   Рамки + классы + уверенность
```

**Ключевые решения:** перенос обучения с COCO, замена `box_predictor` под наши классы, два этапа дают высокую точность локализации мелких объектов.

#### Подход 2 — YOLOv8 (одноуровневый детектор)

```
Входное изображение (3 × 800 × 800)
            ↓
┌─────────────────────────────────────┐
│   YOLOv8 (предобучен на COCO)        │
│   Единый проход сети: классы и рамки │
│   предсказываются одновременно       │
│   → высокая скорость (real-time)     │
└─────────────────────────────────────┘
            ↓
   Рамки + классы + уверенность за 1 проход
```

**Ключевые решения:** перенос обучения с COCO, встроенные аугментации `mixup`/`copy_paste` для борьбы с дисбалансом, единый проход сети для скорости.

#### Гиперпараметры обучения

| Параметр | Faster R-CNN | YOLOv8 |
|---|---|---|
| Входное разрешение | 800 × 800 | 800 × 800 |
| Batch size | 2 | 8 |
| Оптимизатор | SGD (lr=0.005, momentum=0.9) | auto (Ultralytics) |
| LR scheduler | Cosine + warmup | встроенный |
| Эпохи | 30 | 150 |
| Аугментации | flip, brightness, hue, shift/scale/rotate | mosaic, mixup, copy_paste, HSV |

### Метрики качества

В проекте реализованы и используются специфичные для детектирования метрики:

- **IoU (Intersection over Union)** — отношение площади пересечения предсказанной и истинной рамок к площади их объединения. Предсказание считается верным (True Positive), если IoU с истинной рамкой того же класса ≥ 0.5.

- **Average Precision (AP)** — площадь под кривой Precision–Recall для класса. Детекции сортируются по уверенности, накапливаются TP/FP, считается AP по методу интерполяции VOC.

- **mean Average Precision (mAP@0.5)** — среднее AP по всем классам при пороге IoU = 0.5. Главная целевая метрика проекта.

Корректность собственной реализации IoU/AP подтверждена юнит-тестами (идеальный детектор → AP=1.0, неверный → 0, найденная половина объектов → 0.5) и перекрёстной сверкой с эталонной библиотекой `torchmetrics`.

### Выводы

В рамках проекта успешно решена задача детектирования медицинских масок с обучением и сравнением **двух семейств детекторов**:

1. **Перенос обучения критичен для маленьких данных.** Обе модели, предобученные на COCO, достигли высокого качества на 853 изображениях — обучение детектора с нуля на таком объёме было бы невозможно.

2. **Дисбаланс классов — главное узкое место.** Редкий класс `mask_weared_incorrect` (всего ~3% объектов) изначально проваливался обеими моделями и тянул общий mAP вниз. Именно борьба за этот класс определяла достижение целевого порога.

3. **Меры против дисбаланса работают.** Повышение разрешения (мелкие лица различимее), усиление аугментаций и техника `copy_paste` (физическое копирование редких объектов между изображениями) заметно подняли AP проблемного класса.

4. **Скорость против точности.** Faster R-CNN точнее локализует мелкие плотные объекты за счёт двух этапов, но медленнее на инференсе. YOLOv8 работает в разы быстрее (один проход сети) и подходит для real-time видеопотока при сопоставимом mAP.

5. **Рекомендация для production.** Для контроля в реальном времени (турникеты, видеопоток на входе) — **YOLOv8**. Для офлайн-анализа статичных снимков с упором на максимальную точность локализации — **Faster R-CNN**.
